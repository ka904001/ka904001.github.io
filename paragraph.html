A little guide

Listen your way

Tap any paragraph to set your place, then Play. Previous and Next move one paragraph. Resume continues near the last spoken word; a short phrase may repeat after an interruption. Voice and speed preferences are saved separately for English and Russian.

Karen and Russian voices

Browser voice mode prefers Karen when the browser exposes her. Media audio uses a separate local English/Russian voice; it does not record Karen. Download system voices in iPhone Settings → Accessibility → Read & Speak (called Spoken Content on some versions) → Voices, then reopen the reader. The browser decides which installed voices are available. Use Test voice to check the actual sound.

Screen locking on iPhone

The supplied iPhone report showed speech stalling inside a paragraph while Safari still reported “speaking”. The new experimental default creates one fresh request from the last confirmed word when Safari becomes hidden, instead of requiring a manual paragraph-end timing trick. A real pending paragraph handoff is preserved. After returning, word progress is checked; one recovery is allowed, then persistent stalls pause with an explanation. A short phrase may repeat. This is not yet verified to prevent the iPhone fade. You can select “Let the paragraph finish” to compare the original behavior. Save a playback report after a failed run. Basic generated audio remains a different voice.

Add to Home Screen

Open your GitHub Pages address in Safari, tap Share, then Add to Home Screen. Open the installed app and import your library there; Safari and Home Screen storage may differ.

Local does not mean guaranteed offline launch

Books and progress live in IndexedDB. Once this page is loaded and a local voice is available, imported text can be read without fetching the original file. This strict single-file edition has no service worker: reopening offline is not guaranteed. EPUB, DOC, DOCX, PDF, and Kindle import libraries are fetched from pinned CDN addresses as needed.

Keep your library safe

Use Back up library before clearing browser data or changing the site address. Persistent storage is requested only when you select Protect local storage; the browser may decline. Books are not synced between devices.

Bring WTR Lab with you

WTR Lab requires sign-in for your example novel. A separate GitHub Pages site cannot read your signed-in WTR Lab session.

Collect chapters in your signed-in browser

  1. On a desktop browser with a userscript manager, install the companion below.
  2. Open the novel on WTR Lab and sign in there as usual.
  3. Open the reading page, set the chapter range, and choose API · fast. Press Start / resume. Choose Page mode if you need WTR’s custom displayed terms.
  4. Choose Export JSON, transfer the file to your iPhone, and import it here. Keep the tab visible when using Page mode.
Open your novel

Collector v3 uses WTR’s chapter API in your existing browser session, with no fixed delay. It follows fresh content links and resolves chapter glossary markers. It saves each chapter locally and stops for sign-in, verification, or locked content. API mode uses the chapter glossary; Page mode copies your displayed terminology and advances as soon as the text is ready. No passwords, cookies, or signed content links are exported.

Why there is no direct URL download here

Cross-origin requests need WTR Lab’s permission (CORS), and sign-in cookies are scoped to WTR Lab. Its current community downloader reports changing API responses, translation glossaries, locked chapters, and verification challenges. The companion therefore lets WTR load chapters in your existing session and collects the rendered text.
